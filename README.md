# Авторизация для demo-exam-2026 в Windows Forms

Здесь разобраны два варианта реализации авторизации в Windows Forms:

- [Авторизация с ORM — Entity Framework Core (рекомендуемый вариант)](AUTH_ENTITY_FRAMEWORK.md)
- [Авторизация без ORM — ADO.NET](AUTH_NO_ORM.md)

## В чём разница

Главное отличие — в том, как приложение работает с базой данных.

**Entity Framework Core (ORM)** позволяет работать с данными через C#-классы и LINQ. EF Core сам выполняет необходимый SQL-запрос к базе данных и преобразует результат обратно в объекты C#.

Схематично:

```text
Windows Forms → C#-объекты / LINQ → Entity Framework Core → SQL → БД
```

**ADO.NET без ORM** работает с базой данных более напрямую: разработчик самостоятельно создаёт SQL-запросы, параметры, подключение и обработку результата.

```text
Windows Forms → ADO.NET → SQL-запрос → БД
```

### Сравнение

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Entity Framework Core (ORM)** | Меньше ручного SQL, работа с БД через C#-объекты и LINQ, меньше повторяющегося кода, удобнее расширять приложение | Нужно разобраться в EF Core и его настройках |
| **ADO.NET без ORM** | Хорошо показывает, как приложение напрямую выполняет SQL-запросы, меньше абстракций | Больше ручного кода: SQL-запросы, параметры, подключение и чтение результатов нужно контролировать самостоятельно |

## Что рекомендуется использовать

**Для этого учебного проекта рекомендуется Entity Framework Core.**

Причины:

- авторизация реализуется через обычный C#-код и LINQ;
- не приходится писать большую часть SQL вручную;
- проще работать с пользователем и его ролью как с объектом C#;
- код проще расширять, если в дальнейшем появятся дополнительные проверки, запросы или работа с другими таблицами;
- структура приложения получается ближе к современному подходу разработки приложений на C#.

Вариант без ORM тоже приведён в учебных целях. Он полезен, чтобы понять, что происходит «под капотом»: как создаётся подключение к БД, выполняется SQL-запрос, передаются параметры и читается результат.

**Итого:** оба способа позволяют реализовать одну и ту же авторизацию, но для основной реализации рекомендуется **Entity Framework Core**, а ADO.NET можно использовать как альтернативный вариант для изучения прямой работы с SQL и БД.

В обоих вариантах сама логика авторизации остаётся одинаковой: пользователь вводит логин и пароль, приложение проверяет их в БД, получает роль и открывает соответствующий интерфейс. Гость может войти без авторизации.
