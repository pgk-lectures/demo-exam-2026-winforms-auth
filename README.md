# Авторизация для demo-exam-2026 в Windows Forms

Здесь разобраны два варианта реализации авторизации в Windows Forms:

- [Авторизация с ORM — Entity Framework Core](AUTH_ENTITY_FRAMEWORK.md)
- [Авторизация без ORM — ADO.NET](AUTH_NO_ORM.md)

## Какой способ выбрать

Оба варианта подходят для учебного проекта, но отличаются уровнем абстракции и количеством ручного SQL-кода.

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Entity Framework Core (ORM)** | Меньше ручного SQL, работа с БД через C#-объекты и LINQ, удобнее расширять проект | Нужно изучить EF Core и его настройки |
| **ADO.NET без ORM** | Простая и прозрачная связь с SQL, хорошо показывает, как приложение напрямую выполняет запросы | Больше ручного кода, SQL-запросы и обработку результатов нужно писать самостоятельно |

**Для учебной работы:** если цель — понять, как приложение напрямую работает с SQL-запросами и БД, удобнее начать с варианта **без ORM**. Если важнее быстрее реализовать авторизацию и дальше расширять приложение, удобнее **Entity Framework Core**.

В обоих вариантах сама логика авторизации остаётся одинаковой: пользователь вводит логин и пароль, приложение проверяет их в БД, получает роль и открывает соответствующий интерфейс. Гость может войти без авторизации.
